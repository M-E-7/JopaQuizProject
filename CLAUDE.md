# JopaQuizProject

Personal quiz application. It serves multiple-choice questions (4 options, exactly one correct), tracks the score (right/wrong), and for each question references the part of the source document where the answer is found.

Questions are generated by Claude from documents the user provides, via the project skill `.claude/skills/generate-quiz/` (see "Generating quizzes").

## Constraints

- Not published to any app store. Used by the owner and shared with a few other people on their own devices.
- Must run on **Windows** and **Android**.
- The user works in **JavaScript / TypeScript**.

| Getting quizzes onto devices | Import a quiz JSON file at runtime via a file picker (no rebuild/redeploy needed). Re-importing a set with the same id asks to replace it (shows question count + date on device vs. file) and keeps its history. Android gets no `accept` filter (its picker can grey out .json files) |
| Score persistence | Local history per quiz set: one run per finished run, saved by `addRun` when Finish / Hand in is tapped or the exam time runs out (date, `mode`, asked `questionIds`, answered-only results `{ questionId, correct }`, exam runs also `exam: { questionCount, timeLimitMinutes, timeUsedSeconds, timedOut }`; Quit / Back mid-run saves nothing). Runs saved before Exam mode have no `mode` / `questionIds`: read as Study runs whose results are their questions (`runMode()`). `mode` is `study` / `exam` / `retry`. Scores are derived by pure functions in `score.ts` (`currentResults`, `runScore`, `historySummary(runs, ids, mode?)`, `stillMissedIds`) counted against the set's **current** question ids, so removed questions are ignored and totals recounted; asked-but-unanswered questions count as missed; stored runs are never rewritten. Shown on the list (latest run of any mode: "Last: Exam 85% (17 of 20) · date · N runs") and on the summary ("Last time: …", the previous run of the **same** mode). `QuizScreen` loads a set's runs once and owns them: runs save through its `saveRun` (`addRun` + append), and get `previous` (frozen at mount) and the live `missedCount` as props |
| Platform layer | `app/src/platform/`: `QuizStorage` + `FileImport` interfaces (`types.ts`), web implementation in `web/` — IndexedDB via the `idb` library, database `jopa-quiz` v2 with stores `quizSets` (key `quiz.id`), `runs` (auto id, index `byQuiz`) and `examSettings` (key `quizId`, added in v2; kept when a set is replaced, deleted with it) |
| Screens / navigation | No router. `App.tsx` shows list → mode choice → run from `history.state` (URL unchanged): Start pushes `{ quizId }` (`ModeChoice`), picking a mode pushes `{ quizId, mode }` (`StudyRun` for study/retry, `ExamRun`), a summary's "Retry missed" **replaces** the run's entry (`switchMode`), so Back (incl. Android's) and Quit go run → mode choice → list; the summary's "Back to list" does `history.go(-2)`. Back or Quit mid-run with answers (or exam marks) asks first ("Leave this quiz/exam?", `ConfirmDialog`); on the exam's review page Back closes the review instead (ExamRun registers a handler via `onBackOverrideChange`, App's `popstate` calls it; no extra history entry, so `go(-2)` still works); a reload reopens the same screen, a run from the start (new order, exam clock restarts) |
| Study / Exam / Retry modes | Picked on the mode choice after Start. **Study** = all questions, instant feedback. **Retry missed** = the still-missed questions (`stillMissedIds`: latest answer in any run wrong or unanswered; a later right answer removes it, never-asked ones aren't in it), played like Study (`StudyRun mode="retry"`, header "Retry missed"), saved as mode `retry`; third panel "Missed questions" (disabled at 0) + "Retry missed (K)" on every summary; a reload on an empty retry shows "No missed questions to retry right now." + Back. **Exam** = `shuffleQuestions(...).slice(0, N)` with a time limit: settings "Questions" (1 … set size) and "Minutes" (1 … `MAX_EXAM_MINUTES` 300), defaults 20 / 20 (all if fewer, `examSettingsFor()` in `app/src/exam.ts`), saved per set on Start exam. Tap selects an option (changeable, no feedback, no auto-advance), Previous · ⚑ Mark · Next, Hand in, collapsible "Questions: N of M answered · K marked" grid to jump (marked squares get a ⚑ badge). **Mark** is independent of the answer; marking moves to the next question, tapping "Marked" unmarks and stays; marks live in memory only (not in the result or history). Hand in (and Next → "Review" on the last question) opens the review page (`ExamReview.tsx`): every question with ✓ Answered / — Not answered / ⚑ Marked, marked rows highlighted, sort "Exam order" (default) / "Needs attention first" (marked or unanswered first), tap a row to open it, Back to exam / Hand in; submitting is only possible there and confirms only if some are unanswered or still marked. Countdown from `Date.now()` (keeps running in the background, also on the review page), red in the last minute; at 0 handed in automatically. Unanswered = missed |
| Question / option order | Always shuffled, no switch: `shuffleQuestions()` in `app/src/shuffle.ts` gives each run (mount of `StudyRun` / `ExamRun`) a random order of questions and of each question's options, with `correctIndex` remapped. In memory only, so Start again and a reload reshuffle; stored ids and results are unaffected |
| Answering | Study: one tap answers at once (no Check step): options lock, correct one green ✓, wrong pick red ✗, explanation shown, then Next. Marks use icon + colour, not colour alone. Exam: the picked option is marked in the accent colour (filled letter + dot), never green/red before hand-in; a ⚑-marked question uses accent too (highlighted Mark button, "⚑ Marked" badge in the header) |
| End-of-quiz summary | `QuizSummary.tsx` (all modes; "Quiz finished" / "Exam finished" / "Retry finished"): percentage + "N of M correct" (M = questions in the run, so unanswered count as missed) + for exams "Time used: m:ss of m:ss" (+ "Time ran out — …") + muted "Last time: P% (N of M) · date" if the set has an earlier run in that mode (and an error panel if saving failed), then "Missed questions (K)" as collapsed `<details>` rows ("Question N" + 2-line preview) that open to the full question, ✗ your answer (or "Not answered"), ✓ correct answer (option text, no letters), explanation, source. Buttons: Start again (remounts the run, same mode and settings; not after a retry), "Retry missed (K)" (once the run is saved and K > 0; primary after a retry, where it starts the next round) and Back to list. The picked option (`Answer.chosen` in `score.ts`) lives in memory only; stored history stays `{ questionId, correct }` |

## Privacy / public repo

- The GitHub repo is public. **Never commit anything from `documents/` or `quizzes/`** — both are gitignored.
- Quiz JSON files are transferred to devices manually and imported in the app; they are never part of the deployed site.

## Architecture rule

- File import and storage go through the platform interface: UI code uses `platform.storage` / `platform.files` from `app/src/platform/index.ts` and must not call IndexedDB or file APIs directly, so the app can later be wrapped (Tauri / Capacitor) by changing only `index.ts` and adding an implementation.
- Saving a quiz set requests persistent storage (`navigator.storage.persist()`) once per session. Replacing a set (same id) keeps its history and exam settings; deleting a set deletes both too.
- Changing the stored data: bump `DB_VERSION` in `app/src/platform/web/idb-storage.ts` and add an `if (oldVersion < N)` step in `upgrade` that converts existing data (see "Data compatibility rule").

## Installing on devices

- **Windows:** open https://m-e-7.github.io/JopaQuizProject/ in Edge (address-bar "App available" icon, or ⋯ → Apps → Install this site as an app) or Chrome (install icon, or ⋮ → Cast, save, and share → Install page as app).
- **Android:** open the URL in Chrome → ⋮ → "Install app" / "Add to Home screen".
- Clearing the site's data in the browser wipes that device's quizzes and score history — never suggest it as a fix.

## Updating the app

1. Claude changes `app/`, makes sure `npm run build` and `npm run lint` pass, and gives a commit message.
2. The user commits and pushes to `main`; the deploy workflow publishes it (~1–2 min, GitHub's CDN can serve old files for up to ~10 min).
3. Installed apps update themselves, but it takes **two launches while online**: the first launch shows the old (cached) version and downloads the new one in the background; the next launch runs the new version.
   - Windows: close and reopen the app window, or F5 / Ctrl+R inside it. If stuck: Ctrl+Shift+R.
   - Android: fully close the app (swipe it away in recent apps) and reopen.
   - Home-screen name/icon changes can take up to ~a day on Android.
4. To check that a device has the update, compare the footer label (`build date · commit hash`) with the latest commit on `main`. The planned "new version available → Reload" notice (Phase 4) will make updating easier.

**Data compatibility rule:** imported quizzes and score history live in IndexedDB on each device and survive app updates. Any change to how data is stored must migrate existing data (bump the IndexedDB version and convert in the upgrade handler) — never drop or silently ignore a user's stored quizzes or history.

## Commands

Run from `app/`:

```bash
npm install      # once, or after dependency changes
npm run dev      # dev server with hot reload (http://localhost:5173/JopaQuizProject/)
npm run build    # type-check (tsc -b) + production build into app/dist/
npm run preview  # serve the production build locally
npm run lint     # oxlint
npm run generate-pwa-assets  # regenerate PNG/ICO icons in public/ after editing public/favicon.svg
npm run validate-quiz -- ../quizzes/x.json  # check quiz files or folders (exit 1 on errors)
npm run ingest -- ../documents/x.docx       # extract a document's text for question generation (see "Ingestion")
npm run check-references -- ../quizzes/x.json  # every quote appears at its location in documents/extracted/
npm run quiz-blind -- ../quizzes/x.json [--ids q0001-q0040]  # questions + options without answers (for the blind check)
npm run quiz-coverage -- ../quizzes/x.json [--unused]  # which document paragraphs/rows the questions use + next free id
```

- `validate-quiz`, `ingest`, `check-references`, `quiz-blind` and `quiz-coverage` resolve paths from where npm was started, so from the repo root use `npm --prefix app run validate-quiz -- quizzes/x.json` / `npm --prefix app run ingest -- documents/x.docx`.

- `.claude/launch.json` defines `app-dev` (dev server, port 5173) and `app-preview` (production build, port 4173) for Claude's browser preview. Vite `base` is `/JopaQuizProject/` everywhere (dev, preview, production), so after starting either one navigate to `/JopaQuizProject/` — the bare origin returns 404. The service worker only runs in the production build, so test PWA/offline behaviour with `npm run build` + `app-preview`.
- The dev server's file watcher on Windows can miss a second quick edit to the same file (it keeps serving the older version). If the browser doesn't reflect an edit, touch the file (`(Get-Item <file>).LastWriteTime = Get-Date`) and reload.
- To get quizzes into the dev server for testing, save them from `javascript_tool` via `(await import('/JopaQuizProject/src/platform/index.ts')).platform.storage.saveQuizSet(...)` — files outside `app/` (e.g. `quizzes/`) can't be fetched from the dev server (403).

## PWA setup

- `vite-plugin-pwa` (config in `app/vite.config.ts`): web manifest, Workbox service worker (`generateSW`) that precaches the whole app shell, so the app works fully offline.
- `registerType: 'autoUpdate'` with the plain `registerSW.js` script (no `virtual:pwa-register` import): the new service worker activates in the background, but the open page is not reloaded — hence the two-launch update. The Phase 4 "new version available" notice will need `'prompt'` and the `virtual:pwa-register` module instead.
- Icons: single source `app/public/favicon.svg` (four answer bars, one green with a check mark). `app/pwa-assets.config.ts` generates the PNG/ICO sizes; maskable and Apple icons use the brand blue `#2563eb` as background. Generated icons are committed.
- Theme: `app/src/index.css` defines colour tokens (`--text`, `--bg`, `--surface`, `--accent`, `--on-accent` (text on accent backgrounds), `--correct`, `--wrong`, `--on-wrong`, …) for light and dark (`prefers-color-scheme`). Use the tokens, not hard-coded colours. Shared classes: `.panel` (`.error` / `.success`), `.button` (`.primary`, `.danger` for destructive actions), `.actions`; buttons are at least 44px tall for touch.

## Quiz file format

Full spec: `schema/README.md`. Key rules:

- Exactly 4 unique options, one `correctIndex` (0–3), required `explanation` and `reference` with a verbatim `quote`.
- Question ids `q0001`, `q0002`, … are stable: never renumber or reuse them (score history refers to them). Appended questions get the next free number (above every id in `questions` and `removedQuestionIds`).
- A question whose fact disappeared from the document is deleted and its id added to the optional `removedQuestionIds`; the app must ignore score history for those ids (Phase 3). Ids may therefore have gaps.
- If the format changes, update the schema, `schema/README.md`, `schema/examples/example-quiz.json` and `app/src/quiz/types.ts` together, bump `formatVersion` for breaking changes (and `SUPPORTED_FORMAT_VERSION` in `validate.ts`), and run `validate-quiz` on the example.

## Source documents

- **.docx** — `location.type: "section"` with the heading path to the section, plus a verbatim quote of the passage containing the answer.
- **.csv** — content varies: may be a fact table (e.g. term/definition) or ready-made Q&A rows. `location.type: "row"` with the spreadsheet row number (header = row 1) and column names; quote as `Column: value | Column: value`.

### Generating quizzes

- Use the project skill `.claude/skills/generate-quiz/` (`/generate-quiz <file in documents/>`): ingest → read `documents/extracted/<file>.md` → write `quizzes/<id>.json` → `validate-quiz` + `check-references` until clean → independent blind check → report.
- Independent check (user's choice): a fresh `general-purpose` subagent (same model) reads the extracted document and answers the questions from `npm run quiz-blind` without opening `quizzes/`; mismatches with `correctIndex` and "ambiguous" flags are fixed or the question dropped (renumbering is OK only before first import), and the report says how many agreed and what changed. It checks against the document only, not real-world facts (for practice items: the item's own passage is the only source of facts, the guide supplies the rules). Split into `--ids` ranges for over ~40 questions.
- Adding to an existing set (user's choices): append mode of the same skill (section "Adding questions to an existing set"), never a new skill. Back up to `quizzes/backup/`, re-ingest, `check-references` finds existing questions the document change broke (moved quote → fix location; changed fact → fix in place, same id; fact gone → remove + `removedQuestionIds`), `quiz-coverage --unused` shows uncovered paragraphs/rows and the next free id, Claude also compares wording with existing questions, then new questions are appended, `updatedAt` set, blind check on new + changed ids only.
- What the questions test depends on the document (user's choice, from the EPSO guide): **reference material** (manuals, rules, glossaries, Q&A CSVs) → fact questions; a **document that teaches a skill or method** (exam-prep guide) → **practice items** modelled on the real task (e.g. an original Croatian passage + "Koja je od sljedećih izjava točna?", one entailed statement, each wrong one built on a trap from the guide), one item per rule, with the guide's rule as `reference`. Same quiz format (passage paragraphs separated by `\n\n` in `question`). The skill says which kind it chose.
- Defaults (user's choices): cover the document (one question per testable fact; ask first if over ~60); mostly recall plus ~¼ understanding questions; Q&A CSVs keep the user's wording (obvious typos fixed) and their A–D options; never overwrite an existing quiz set.
- `check-references` matches quotes ignoring spacing and typographic quote/dash variants. A quote may run over consecutive paragraphs (a list split into items, joined with `\n`, labels optional), starting at `location.paragraph`. For CSV, every `Column: value` part must be in that row and listed in `location.columns`.

### Ingestion (`npm run ingest`)

- Before writing questions, run `npm --prefix app run ingest -- documents/<file>` (or a folder). It writes `documents/extracted/<file>.md` (read this) and `.json` (structured, for later quote checks). Gitignored.
- The `.md` gives every passage its exact location: `headingPath: [...]` per section and `[pN]` paragraph numbers (1-based within the section, list items and table rows count as paragraphs); CSV rows as `[row N] Column: value | …`, already in quote format. Copy locations and quotes from it verbatim.
- Code: `app/scripts/ingest/` — one reader per format registered in `readers.ts` (`docx.ts`, `csv.ts`), shared model `model.ts`, Markdown view `render.ts`. A new format = a new reader returning a `ReaderResult` + one line in `readers.ts`.
- .docx: own reader (fflate + @xmldom/xmldom). Headings come from built-in heading styles (English internal name in any Word language) or outline level. Word's automatic numbering is rebuilt (headings read "2.1 Helmets", list items get "3." / "a)" / "•"). Not extracted: images, text boxes, footnotes, headers/footers, comments (counted in the notes).
- .csv: papaparse. Separator auto-detected (`,` `;` tab `|`). Encoding: BOM → UTF-8/16, else UTF-8, else **Windows-1250** (Croatian Excel); override with `--encoding windows-1252` etc. Shape guess `qa` / `facts` / `unknown` from column names (English and Croatian, e.g. Pitanje, A–D, Točan odgovor) or cells ending in `?`. It's a hint; the question generator decides.

## Repository layout

- `documents/` — source documents to generate questions from (**gitignored** except its README). `documents/extracted/` holds `npm run ingest` output.

- `app/` — the React PWA (Vite project: `src/`, `public/` icons, `vite.config.ts`, `pwa-assets.config.ts`).
  - `app/src/quiz/` — quiz format types (`types.ts`, keep in sync with the schema) and the validator (`validate.ts`; no DOM or Node APIs, it runs in both).
  - `app/src/platform/` — platform interface (`types.ts`), the `platform` object the UI uses (`index.ts`), web implementations (`web/idb-storage.ts`, `web/file-import.ts`).
  - `app/src/components/` — UI components (`ImportQuiz.tsx`, `QuizList.tsx` with Start and Delete buttons (Delete is confirmed in `App.tsx`) and each set's last score (App loads the runs with the list, and reloads them on returning from a quiz), `QuizScreen.tsx` — loads the set and its runs and shows `ModeChoice.tsx` (Study / Exam + exam settings / Retry missed), `StudyRun.tsx` (Study and Retry: question, options, answer feedback, running score ✓ correct · ✗ wrong, progress bar) or `ExamRun.tsx` (countdown, selectable options, Previous / Mark / Next / Hand in, overview grid, marks), `ExamReview.tsx` (the review page before handing in), `QuizSummary.tsx` — end-of-quiz score, percentage and missed questions, `SourceReference.tsx` — the answer's source (document, location, quote), `ConfirmDialog.tsx` — reusable modal yes/no, `danger` for destructive confirms); `app/src/format.ts` — small text helpers (`plural`, `formatDate`, `formatDuration`, `OPTION_LETTERS`); `app/src/exam.ts` — exam defaults/limits and `examSettingsFor()`; `app/src/score.ts` — the in-memory `Answer` type and pure score figures derived from run results (`countResults`, `scorePercent`, and for saved history `runMode`, `currentResults`, `runScore`, `historySummary`, `stillMissedIds`); `app/src/shuffle.ts` — `shuffled()` and `shuffleQuestions()` for a run's random order.
  - `app/scripts/` — Node command-line scripts (type-checked by `tsconfig.scripts.json`): `validate-quiz.ts`, `ingest.ts` + `ingest/`, `check-references.ts`, `quiz-blind.ts`, `quiz-coverage.ts`; `extracted.ts` holds the shared loading/text-matching helpers for the scripts that read `documents/extracted/`. Imports between `.ts` files need the `.ts` extension so Node can run them, and no TypeScript-only runtime syntax (enums, constructor parameter properties). Their libraries are devDependencies; only `ajv`/`ajv-formats` ship in the app.
- `.github/workflows/deploy.yml` — build + deploy to GitHub Pages.
- `.claude/launch.json` — dev/preview server configs for Claude's browser pane.
- `.claude/skills/generate-quiz/` — the question-generation skill.
- `GUIDE.txt` — the owner's how-to for processes (generating quizzes, getting them onto devices, installing, updating the app, commands, troubleshooting).
- `todo.md` — open tasks, grouped by phase, with a "Where we are" note at the top.
- `completedTasks.md` — finished tasks with completion date (newest first).

## Workflow rules for Claude

- **Never commit or push.** The user commits and pushes manually.
- "Let's go next task" means: take the first open task in `todo.md` (check the "Where we are" note first).
- After each completed task:
  1. Move it from `todo.md` to `completedTasks.md` (with the date and how it was verified) and refresh the "Where we are" note.
  2. Update this file if the task produced a decision, a new convention or new commands.
  3. Update `GUIDE.txt` if a process the owner follows changed (making quizzes, importing, installing, updating, commands), including its "Last updated" line. It's the owner's plain-language how-to for when they've been away, so keep it short, practical and free of internals.
  4. Give the user a suggested git commit message in a code block. Keep it short: a subject line, plus at most 2–3 short lines only if really needed. No `Co-Authored-By` or other attribution lines.
- Before finishing a task that touches `app/`, run `npm run build` and `npm run lint` and make sure both pass; check UI changes in the browser pane (`app-dev`, or `app-preview` for PWA/offline).
- For significant decisions, discuss pros and cons and let the user choose (they like to understand trade-offs). Ask when something is unclear rather than guessing.
- When the user has to do something themselves (GitHub settings, installing on devices), give a short step-by-step guide.
- The app also runs on other people's devices — keep stored data compatible across updates (see "Updating the app").
