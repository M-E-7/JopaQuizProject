1. WHAT IS WHERE
----------------

Project folder:  C:\JopaQuizProject

backed up by GitHub. Keep your own backup of quizzes\ (and documents\) if you
care about them, e.g. a copy on OneDrive or a USB stick.


2. WORKING WITH CLAUDE ON THIS PROJECT
--------------------------------------

- Open the project folder (C:\JopaQuizProject) in Claude Code (desktop app,
  Code tab).
- "next task" = Claude takes the first open task from todo.md and does it.
- "where are we?" = Claude reads todo.md / completedTasks.md and summarises.
- Claude never commits or pushes. At the end of a task it gives you a commit
  message; you commit and push yourself (see section 7).
- After each task Claude updates todo.md, completedTasks.md and, if needed,
  CLAUDE.md and this guide.
- For bigger decisions Claude explains the options and lets you choose.


3. MAKING A QUIZ FROM A DOCUMENT
--------------------------------

1. Copy the document into C:\JopaQuizProject\documents\
   - Supported: .docx (Word) and .csv (Excel: File > Save As > CSV).
   - Old .doc files: open in Word and "Save As" .docx first.
   - Word: use real heading styles (Heading 1, Heading 2, ...) for chapter
     titles; that's how question references find "chapter 2.1".
   - CSV: first row = column names. Either a fact table (e.g. Pojam;Značenje)
     or ready-made questions (e.g. Pitanje;A;B;C;D;Točan odgovor).

2. Ask Claude, for example:
     /generate-quiz documents/Pravilnik.docx
     make a quiz from documents/Pojmovi.csv
     make 20 questions from the safety manual
     make one quiz from Pravilnik.docx and Pojmovi.csv
   Optional: a number of questions, or a quiz id (file name).

3. Claude then:
   - extracts the text (npm run ingest),
   - writes quizzes\<quiz-id>.json,
   - runs the two checks (format + "every quote really is in the document"),
   - has a second Claude answer the quiz "blind" from the document (without
     seeing the answers); where it disagrees or finds two right options,
     Claude fixes or drops the question,
   - shows you a summary: how many answers the second check agreed with,
     what it changed, and a few sample questions.
   This checks the questions against the document, not against the real
   world: if the document is wrong or outdated, so is the quiz.
   By default it covers the whole document (one question per testable fact)
   and asks first if that would be more than ~60 questions.

   What kind of questions depends on the document:
   - Manuals, rules, glossaries, question lists -> questions about what the
     document says ("How often must ... be checked?").
   - A guide that teaches how to solve a type of task (e.g. the EPSO verbal
     reasoning skripta) -> practice tasks: Claude writes new short texts with
     four statements, each wrong one built on a trap from the guide. After
     answering, the app shows the guide's rule that decides the task.
   Claude says which kind it picked; tell it if you want the other kind.

4. Read the samples. If something's off, just say so ("distractors too easy",
   "skip chapter 5", "fewer questions") and Claude fixes the file.

Notes
- Questions are written in the document's language.
- Claude never overwrites an existing quiz file; it asks first. (Device score
  history is tied to question ids q0001, q0002, ...)

Adding questions to an existing quiz
- When the document got new material (save the new version over the old
  file in documents\), or another document should join the quiz, ask e.g.:
     add questions to quizzes/epso-verbalno-zakljucivanje.json from the
     updated EPSO_Verbal_skripta_HR_knjiga.docx
- Claude first saves a backup in quizzes\backup\, then:
   - fixes existing questions whose text changed in the document (they keep
     their id, so score history stays),
   - removes questions whose fact is gone from the document (their id is
     never used again),
   - adds questions only for parts no question covers yet.
  The summary lists everything added, fixed and removed.
- Afterwards import the file again on each device; it replaces the old
  version and keeps the score history.


4. CHECKING A QUIZ BY HAND
--------------------------

From C:\JopaQuizProject in a terminal (PowerShell is fine):

  npm --prefix app run validate-quiz -- quizzes\my-quiz.json
      -> format check: "OK, 25 questions from 1 source" or a list of errors

  npm --prefix app run check-references -- quizzes\my-quiz.json
      -> every quote appears at its stated place in the document

  npm --prefix app run quiz-blind -- quizzes\my-quiz.json
      -> questions and options without the answers (what the blind check
         reads; also handy for testing yourself)

  npm --prefix app run quiz-coverage -- quizzes\my-quiz.json --unused
      -> parts of the document no question asks about yet

  npm --prefix app run ingest -- documents\Pravilnik.docx
      -> re-extract a document (needed after you edit it;
         check-references warns when the document changed)

You can open quizzes\*.json in any text editor (VS Code, Notepad) to fix
a typo. Don't change question ids. Run validate-quiz afterwards.


5. GETTING A QUIZ ONTO A DEVICE
-------------------------------

1. Copy quizzes\<quiz-id>.json to the device:
   - Windows: just keep it on the PC, or put it on OneDrive.
   - Android: email it to yourself, Google Drive, USB cable, ... - anything
     that lands it in Downloads/Files.
2. In the app: "Import quiz from file" -> pick the .json file.
   - The quiz appears in the list with its number of questions.
   - On Android the picker shows all files; just pick the .json one.
   - A wrong or broken file is refused with a list of what's wrong (give
     that list to Claude). "Warnings" after a successful import don't stop
     anything; the quiz works.
3. Importing a file with the same quiz id again (e.g. after Claude fixed a
   typo or added questions) asks "Replace it?" and shows the number of
   questions and the date on the device vs. in the file, so you don't
   replace a newer version with an older one. Your score history is kept.

4. Playing: "Start" next to a quiz, then pick a mode:
   - Study: all questions. Tap an answer - it counts at once (no undo), the
     right one turns green and the explanation appears; "Next".
   - Exam: a random pick of questions with a time limit (default 20
     questions and 20 minutes; change both on that screen, the app
     remembers them per quiz on that device). Nothing is marked while you
     answer; you can change answers and move with Previous / Next or the
     "Questions: N of M answered" grid. "Mark" flags a question to come
     back to later and moves on (tap "Marked" to unmark; you can mark a
     question you've answered too). "Hand in" (or "Review" on the last
     question) opens a review page with every question - answered, not
     answered, marked - which you can sort by "Needs attention first";
     tap a row to go back to it. "Hand in" there ends the exam (it asks
     first if some are unanswered or still marked); at 0:00 it is handed
     in automatically. Unanswered questions count as wrong.
   - Missed questions ("Retry missed"): only the questions you got wrong
     or left unanswered the last time you saw them, checked at once like
     Study. Answer one right and it drops off the list; get it wrong again
     (in any mode) and it stays. Greyed out when there's nothing to retry.
     The end-of-run screen also has a "Retry missed (N)" button.
   In every mode the questions, and the answers within each question, come in
   a new random order every time. "Quit" or the back button goes back to
   the mode choice (it asks first if you've answered something, because a
   run left half-way isn't saved); back again returns to the list.
   At the end you see your score (percentage, "N of M correct", time used
   for an exam, and "Last time" for the previous run in the same mode) and
   the missed questions - tap one to see your answer, the right one, the
   explanation and the source. "Start again" plays again in the same mode.
   Every finished run is saved on that device. The list shows the latest
   one with its mode and the number of runs ("Last: Exam 85% (17 of 20) ·
   date · 3 runs"). After a re-import, questions that were removed no
   longer count.

5. Deleting: "Delete" next to a quiz, then confirm. It removes the quiz and
   its score history from that device only (other devices keep theirs). You
   can import the file again, but the history doesn't come back.

To share with someone: send them the .json file and the app link.


6. INSTALLING THE APP ON A DEVICE
---------------------------------

Link: https://m-e-7.github.io/JopaQuizProject/

Windows (Edge):   open the link -> "App available" icon in the address bar
                  (or ... menu -> Apps -> Install this site as an app)
Windows (Chrome): open the link -> install icon in the address bar
                  (or menu -> Cast, save, and share -> Install page as app)
Android (Chrome): open the link -> menu (three dots) -> "Install app" /
                  "Add to Home screen"

Once installed it works offline.

IMPORTANT: clearing the browser's "site data" / "storage" for this site
DELETES that device's quizzes and score history. Never do that as a "fix".


7. UPDATING THE APP (NEW VERSION)
---------------------------------

1. Claude changes the code and gives you a commit message.
2. You commit and push to main:
   - GitHub Desktop: write the message, "Commit to main", then "Push origin"
   - or in a terminal from C:\JopaQuizProject:
       git add -A
       git commit -m "message from Claude"
       git push
   (git add -A is safe: documents\ and quizzes\ are ignored.)
3. GitHub builds and publishes it automatically (~1-2 minutes):
   https://github.com/M-E-7/JopaQuizProject/actions
   -> "Deploy to GitHub Pages" should turn green.
   Only pushes that change app\ or the quiz schema trigger a deploy;
   doc-only changes don't.
4. Devices update themselves, but it takes TWO launches while online:
   the first launch shows the old version and downloads the new one,
   the second launch runs the new one.
   - Windows: close and reopen the app window (or F5 / Ctrl+R).
     If stuck: Ctrl+Shift+R.
   - Android: swipe the app away in recent apps, reopen. Twice.
   - GitHub can serve old files for up to ~10 minutes after a deploy.
5. Which version is a device running? Look at the small grey label at the
   bottom of the app: "2026-10-18 · a5a8217" = build date · commit.
   Compare the commit with the latest one on GitHub (repo front page).


8. DEVELOPER COMMANDS
---------------------

Needs only Node.js (version 24). Run these in C:\JopaQuizProject\app

  npm install        after a fresh clone or when dependencies changed
  npm run dev        local dev server: http://localhost:5173/JopaQuizProject/
  npm run build      type check + production build (into app\dist)
  npm run preview    serve the production build: http://localhost:4173/JopaQuizProject/
  npm run lint       code checks

(The address must end in /JopaQuizProject/ - the bare localhost:5173 shows 404.)

New PC: install Node.js 24 and Git, clone the repo, run "npm install" in app\,
copy your documents\ and quizzes\ from your backup.


9. TROUBLESHOOTING
------------------

Deploy failed (red X in GitHub Actions)
  -> open the failed run, copy the red error lines, give them to Claude.

"npm ci" / "npm install" fails half-way on Windows
  -> a running dev/preview server locks files. Stop it, try again.

CSV letters look wrong (Znaèenje instead of Značenje)
  -> the file isn't UTF-8. Claude re-runs ingest with --encoding windows-1252
     (or similar). Better: in Excel save as "CSV UTF-8".

check-references says a quote isn't found
  -> the quote must be copied from the document exactly. If you edited the
     document, run ingest again first. Claude fixes these itself during
     generation.

App on a device still shows the old version
  -> see section 7 step 4 (two launches). Check the version label.
     Do NOT clear site data.


10. RULES WORTH REMEMBERING
--------------------------

- The GitHub repo is PUBLIC: never put documents or quizzes into git
  (they're ignored automatically - don't force-add them).
- Back up quizzes\ yourself; GitHub doesn't have them.
- Don't renumber or reuse question ids in a quiz file.
- Never clear the app's site data on a device.
